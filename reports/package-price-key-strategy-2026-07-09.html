package_price.xlsx 전환 및 항목코드 전략 분석

작성일: 2026-07-09 KST · 대상: E:\quotation-management

파일명
package_price.xlsx 권장
시트명
base_item(A), base_product(B) 가능
Track B 키
순번 유지 + 항목코드 추가

1. 결론

가격표.xlsx를 package_price.xlsx로 바꾸는 방향은 좋습니다. 기초견적항목은 base_item(A), products는 base_product(B)로 바꾸면 Track A/B 기준 데이터가 명확해집니다.

다만 base_product(B)의 A컬럼 순번을 항목코드로 단순 대체하는 것은 권장하지 않습니다. 순번은 정렬용으로 유지하고, 별도 항목코드 컬럼을 추가하는 방식이 가장 안전합니다.

2. 확인한 현재 구조

현재 시트역할핵심 컬럼
기초견적항목Track A 레거시 단가합산 기준항목코드, 품목명, 분류, 단위, 기본단가, 제3단가
productsTrack B 상품 마스터순번, 상품계층, 내부제품명, 가격 컬럼, 등록상태, 식별번호
package_preset_itemsTrack B 프리셋 구성프리셋코드, 구성항목, 조달등록후보, 수량, 단가_VAT포함

3. 이름 변경 판단

변경판단이유
가격표.xlsx -> package_price.xlsx권장코드/배포 경로 안정성, 역할 명확성, 향후 버전 관리에 유리합니다.
기초견적항목 -> base_item(A)가능Track A 기준 데이터임이 명확합니다.
products -> base_product(B)권장Track B 상품 마스터임이 명확합니다.
괄호가 포함된 시트명은 Excel/openpyxl에서 사용할 수 있습니다. 단, 수식 참조 시에는 'base_product(B)'!A1처럼 작은따옴표가 필요합니다.

4. 순번 vs 항목코드

항목용도키 사용 적합성
순번엑셀 행 정렬, UI 표시 순서영구키로 부적합. 행 삽입/정렬 시 의미가 바뀔 수 있습니다.
항목코드상품 영구 식별자, 견적 저장, 프리셋 참조, 감사 추적영구키로 적합. 한 번 발급하면 변경하지 않아야 합니다.
식별번호조달 등록 외부 번호내부 상품키로 부적합. 항목코드와 분리해야 합니다.

6. 기존 코드 재사용 정책

기존 base_item(A)의 항목코드는 그대로 유지하는 것이 맞습니다. 기존 저장 견적, 불러오기, 출력 로직이 이미 이 코드를 기준으로 동작합니다.

상황권장 정책
Track A와 완전히 같은 품목기존 항목코드 재사용 가능
Track B 전용 신규 패키지/상품새 항목코드 발급
조달 등록품목내부 항목코드와 외부 식별번호 분리 보관
신규등록후보먼저 신규 항목코드를 발급하고, 등록 완료 후에도 유지

7. Track B 코드 체계 제안

상품계층Prefix예시
CoreB-COREB-CORE-001
ChannelB-CHB-CH-001
UserB-USERB-USER-001
InterfaceB-IFB-IF-001
ModuleB-MODB-MOD-001

코드에는 가격, 버전, 등록상태를 넣지 않는 것이 좋습니다. 가격과 등록상태는 바뀔 수 있지만, 상품 식별자는 바뀌면 안 됩니다.

10. 최종 권고

최종 권고: package_price.xlsx 전환은 진행하되, base_product(B)는 순번을 정렬용으로 남기고 항목코드를 별도 영구키로 추가하십시오.

기존 base_item(A)의 코드는 그대로 유지하고, 신규등록후보와 Track B 전용 상품에는 별도 B 계열 코드를 발급하는 것이 견적 이력, 조달 식별번호, 패키지 프리셋을 모두 안정적으로 연결하는 방법입니다.
