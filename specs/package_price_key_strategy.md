# package_price.xlsx 전환 및 Track B 항목코드 전략

작성일: 2026-07-09 KST
대상: `E:\quotation-management`

## 결론

`가격표.xlsx`는 `package_price.xlsx`로 변경하는 것이 적합하다.
시트명은 요청대로 `기초견적항목` -> `base_item(A)`, `products` -> `base_product(B)`로 변경할 수 있다.

단, `base_product(B)`의 A컬럼 `순번`을 `항목코드`로 대체하는 방식은 권장하지 않는다.
`순번`은 화면 정렬과 엑셀 관리용으로 유지하고, 별도 `항목코드` 컬럼을 추가해 Track B의 영구 식별자로 사용해야 한다.

## 확인한 현재 상태

현재 `가격표.xlsx` 시트는 다음 구조다.

| 시트 | 역할 | 핵심 컬럼 |
|---|---|---|
| `기초견적항목` | Track A 레거시 단가합산 기준 | `항목코드`, `품목명`, `분류`, `단위`, `기본단가`, `제3단가`, `설명` |
| `products` | Track B 상품 마스터 | `순번`, `상품계층`, `내부제품명`, `외부조달표현`, `단위`, 가격 컬럼, `등록상태`, `식별번호` |
| `package_preset_items` | Track B 프리셋 구성 | `프리셋코드`, `구성항목`, `조달등록후보`, `수량`, `단가_VAT포함` |

현재 코드는 다음 방식으로 가격표를 읽는다.

| 파일 | 현재 의존 |
|---|---|
| `catalog_db.py` | `PRICE_XLSX = "가격표.xlsx"`, `products` 시트 적재, `순번` 정렬 |
| `data_manager.py` | Track A 기본값 `가격표.xlsx`, `기초견적항목` |
| `cpq_engine.py` | Track B 구성항목을 제품명+단가로 `products`에 추정 매칭 |
| `main.py` | Track B 저장 시 `식별번호` 또는 `품목명[:20]`을 임시 `항목코드`로 사용 |

## 파일명/시트명 변경 판단

### `가격표.xlsx` -> `package_price.xlsx`

권장한다.

이유:

- 코드와 배포 환경에서 한글 파일명보다 경로 안정성이 좋다.
- 파일 역할이 가격표 일반 문서가 아니라 패키지 CPQ 기준 마스터임을 분명히 한다.
- 향후 `package_price_2026Q3.xlsx`, `package_price.v1.xlsx` 같은 버전 관리로 확장하기 쉽다.

### `기초견적항목` -> `base_item(A)`

허용한다.

Track A 기준 데이터임이 명확해진다. 다만 괄호가 있는 시트명은 Excel 수식에서 항상 `'base_item(A)'!A1`처럼 따옴표 참조가 필요하다.

### `products` -> `base_product(B)`

권장한다.

Track B의 기준 상품 마스터라는 의미가 분명해진다.

기술적으로 더 단순한 이름은 `base_item_A`, `base_product_B`지만, 사용자가 엑셀에서 Track A/B를 즉시 구분해야 한다면 `base_item(A)`, `base_product(B)`도 충분히 가능하다.

## `순번`과 `항목코드` 판단

### 권장 구조

`base_product(B)`에는 `순번`을 유지하고 `항목코드`를 추가한다.

권장 컬럼 순서:

| 순서 | 컬럼 | 용도 |
|---:|---|---|
| 1 | `항목코드` | 시스템 영구 식별자 |
| 2 | `순번` | 화면/엑셀 정렬 순서 |
| 3 | `상품계층` | Core, Channel, User 등 구조 분류 |
| 4 | `내부제품명` | 내부 관리명 |
| 5 | `외부조달표현` | 고객/조달 표시명 |
| 6 | `단위` | 견적 단위 |
| 7+ | 가격/등록/정책 컬럼 | 기존 유지 |

### `순번`을 키로 쓰면 안 되는 이유

`순번`은 행의 위치와 표시 순서를 뜻한다.
행 삽입, 정렬, 상품군 재배치가 발생하면 값이 쉽게 바뀐다.

따라서 `순번`을 견적 저장, 프리셋 구성, 감사 추적, 견적서 재출력의 기준키로 쓰면 과거 견적이 다른 상품을 가리킬 수 있다.

### `항목코드`가 필요한 이유

`항목코드`는 다음 위치에서 동일하게 쓰일 수 있다.

- `base_product(B)`의 상품 영구키
- `package_preset_items`의 구성품 참조키
- `estimate_items.item_code`의 저장키
- 견적서 출력 항목코드
- 가격 변경 이력과 승인 로그의 감사키

## 기존 코드 재사용 여부

기존 `base_item(A)`의 `항목코드`는 그대로 유지해야 한다.

이유:

- Track A 저장 견적과 불러오기 흐름이 이미 `항목코드`를 기준으로 동작한다.
- 기존 코드 변경은 과거 견적 호환성을 깨뜨릴 수 있다.
- Track A의 `HW-001`, `SW-001` 같은 코드는 이미 업무적으로 의미가 있다.

Track B에서는 다음 원칙을 적용한다.

| 상황 | 권장 |
|---|---|
| Track A와 완전히 같은 품목 | 기존 `항목코드` 재사용 가능 |
| Track B 전용 신규 패키지/상품 | 새 `항목코드` 발급 |
| 조달 등록품목 | 내부 `항목코드`와 조달 `식별번호`를 별도 보관 |
| 신규등록후보 | 신규 `항목코드`를 먼저 발급하고, 등록 완료 후에도 코드는 유지 |

특히 `식별번호`를 `항목코드`로 직접 쓰는 것은 권장하지 않는다.
조달 `식별번호`는 외부 등록 번호이고, 내부 상품의 생명주기와 1:1로 항상 맞지 않을 수 있다.

## Track B 코드 체계 제안

Track B 신규 코드는 Track A와 충돌하지 않는 별도 네임스페이스가 좋다.

예시:

| 상품계층 | 코드 prefix | 예시 |
|---|---|---|
| Core | `B-CORE` | `B-CORE-001` |
| Channel | `B-CH` | `B-CH-001` |
| User | `B-USER` | `B-USER-001` |
| Interface | `B-IF` | `B-IF-001` |
| Module | `B-MOD` | `B-MOD-001` |
| Service | `B-SVC` | `B-SVC-001` |

대안으로 더 제품 중심의 prefix를 쓰려면 `IPX-CORE-001`, `IPX-CH-001`, `IPX-SVC-001`도 가능하다.

운영 규칙:

- 코드는 한 번 발급하면 변경하지 않는다.
- 단가, 명칭, 조달상태 변경은 코드 변경 사유가 아니다.
- 상품이 폐지되면 코드를 재사용하지 않고 `inactive` 처리한다.
- 신규등록후보가 실제 등록품목이 되어도 기존 내부 `항목코드`는 유지하고 `식별번호`만 채운다.

## 구현 변경 범위

실제 반영 시 필요한 변경은 다음과 같다.

| 영역 | 변경 |
|---|---|
| 가격 파일 | `가격표.xlsx` -> `package_price.xlsx` |
| Track A loader | 기본 시트 `base_item(A)` |
| Track B loader | `products` -> `base_product(B)` |
| Track B DB | `항목코드` 컬럼 필수 검증, `순번`은 정렬용 |
| CPQ 엔진 | 이름+단가 추정 매칭보다 `항목코드` 기반 매칭 우선 |
| 프리셋 구성 | `package_preset_items`에 `항목코드` 추가 권장 |
| 견적 저장 | `식별번호` 또는 `품목명[:20]` 임시 코드 제거 |
| 견적 출력 | `항목코드`와 `식별번호`를 분리 표기 |

## 추천 마이그레이션 순서

1. `가격표.xlsx`를 백업 후 `package_price.xlsx`로 복제한다.
2. 시트명을 `base_item(A)`, `base_product(B)`로 변경한다.
3. `base_product(B)`에 `항목코드` 컬럼을 추가한다.
4. 기존 Track A와 동일 품목은 기존 코드를 유지하고, Track B 전용 품목은 새 B 계열 코드를 부여한다.
5. 코드에서는 한 릴리스 동안 구 시트명 fallback을 둔다.
6. `package_preset_items`에 `항목코드`를 추가해 이름+단가 매칭을 제거한다.
7. 검증 스크립트로 중복 코드, 빈 코드, 유효하지 않은 프리셋 참조를 차단한다.
